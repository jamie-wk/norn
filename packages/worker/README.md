# @norn/worker

`createWorker()` for [Norn](https://jamie-wk.github.io/norn/): turns the registry generated by `norn gen` into a production worker process. One Temporal worker per task queue, activities built by the dependency container, a prebuilt or on-the-fly workflow bundle, `/healthz` and `/readyz`, graceful shutdown on SIGTERM, correlation IDs, worker versioning and Prometheus metrics, configured from options or environment variables.

- **`createWorker({ registry })`**: everything above, with misconfiguration (unknown task queues, half-set versioning, bad ports or durations, a provider that cannot be built) failing at startup with a `NornConfigError`.
- **`bundleWorkflows()`**: bundles workflows with Norn's settings (TC39 standard decorators, `.js`→`.ts` resolution, the correlation interceptors), for shipping a prebuilt bundle.
- **`installRuntime()`**: the Temporal runtime with a log level and a Prometheus endpoint.

## Install

```sh
pnpm add @norn/worker @temporalio/worker @temporalio/workflow @temporalio/activity @temporalio/common @temporalio/client
```

Requires Node 22.18+ on a glibc-based system (the Temporal SDK's core is a native module; use images such as `node:24-slim`, not Alpine). Add `@norn/cli` to generate the registry.

## Usage

```ts
// src/worker.ts
import { createWorker, installRuntime } from '@norn/worker';
import { createDataConverter } from '@norn/codec'; // optional: payload encryption
import { registry } from '../.norn/registry.js';

installRuntime(); // NORN_LOG_LEVEL, NORN_METRICS_ADDRESS; before any connection or worker

const worker = await createWorker({
  registry,
  container: { errors: { http: true } }, // 4xx from providers are final, 5xx retried
  dataConverter: process.env.NORN_KEY ? createDataConverter({ keys: { k1: process.env.NORN_KEY }, currentKeyId: 'k1' }) : undefined,
});
await worker.run(); // resolves after a graceful shutdown; rejects if a worker fails
```

`createWorker()` resolves once everything is ready: every singleton dependency and activity is created (so a bad provider fails here), the connection is open, the workflow bundle is built or loaded and the health server listens.

## Environment variables

| Variable | Option | Default | Description |
| --- | --- | --- | --- |
| `TEMPORAL_ADDRESS` | `address` | `localhost:7233` | Temporal frontend address. |
| `TEMPORAL_NAMESPACE` | `namespace` | `default` | Namespace to poll. |
| `TEMPORAL_API_KEY` | `apiKey` | none | API key; turns TLS on. |
| `NORN_TASK_QUEUES` | `taskQueues` | every queue in the registry | Comma-separated subset to poll. |
| `NORN_HEALTH_PORT` | `health.port` | off | Health server port; `0` picks a free one. |
| `NORN_SHUTDOWN_GRACE` | `shutdownGraceTime` | `30s` | How long in-flight activities may run after shutdown starts. Any `Duration`. |
| `NORN_DEPLOYMENT_NAME` | `versioning.deploymentName` | none | Worker deployment name. Set together with `NORN_BUILD_ID`. |
| `NORN_BUILD_ID` | `versioning.buildId` | none | Build ID of this version, such as the git SHA. |
| `NORN_WORKFLOW_BUNDLE` | `workflowBundle` | bundle at startup | Path of a prebuilt bundle from `norn bundle` or `bundleWorkflows()`. |
| `NORN_DEV_CONDITIONS` | `nornWebpackConfigHook({ conditions })` | none | Comma-separated package export conditions for the bundler, e.g. a monorepo source condition. |
| `NORN_METRICS_ADDRESS` | `installRuntime({ metricsAddress })` | off | `host:port` for Prometheus metrics. |
| `NORN_LOG_LEVEL` | `installRuntime({ logLevel })` | `INFO` | `TRACE`, `DEBUG`, `INFO`, `WARN` or `ERROR`. |

Options win over environment variables. Setting only one of `NORN_DEPLOYMENT_NAME` and `NORN_BUILD_ID` is a startup error.

## `createWorker(options)`

```ts
function createWorker(options: CreateWorkerOptions): Promise<NornWorker>;

interface NornWorker extends AsyncDisposable {
  readonly taskQueues: readonly string[];
  readonly state: 'INITIALIZED' | 'RUNNING' | 'STOPPING' | 'STOPPED' | 'FAILED';
  readonly healthPort: number | undefined; // useful with health: { port: 0 }
  readonly config: ResolvedWorkerConfig;
  run(): Promise<void>;
  shutdown(): Promise<void>;
}
```

| Option | Description |
| --- | --- |
| `registry` | **Required.** The `registry` from `.norn/registry.ts`. |
| `taskQueues` | Subset of the registry's task queues to poll. |
| `allowUnknownTaskQueues` | Allow queues no workflow declares, for activity-only workers. Otherwise an unknown queue is a startup error. |
| `address`, `namespace`, `apiKey` | Connection settings. |
| `tls` | `boolean`. For mTLS, pass your own `connection`. |
| `connection` | An existing `NativeConnection`. Norn closes only connections it opened. |
| `versioning` | `{ deploymentName, buildId, defaultBehavior? }` (`defaultBehavior` `'auto-upgrade'` by default, or `'pinned'`), or `false` to ignore the environment. |
| `health` | `{ port, host? }` (host defaults to `0.0.0.0`), or `false`. |
| `shutdownGraceTime` | A `Duration`. |
| `handleSignals` | Shut down gracefully on SIGTERM and SIGINT. Default `true`. |
| `container` | `{ overrides?, errors? }` for the dependency container: replace dependencies, and map activity errors (`errors: { http, map }`, see `@norn/activity`). |
| `workflowBundle` | `{ code }` or `{ codePath }` of a prebuilt bundle. |
| `dataConverter` | Such as `createDataConverter()` from `@norn/codec`. Its `payloadConverterPath` is used when bundling at startup. |
| `plugins` | Temporal worker plugins. |
| `activityInterceptors` | Extra activity interceptor factories, after Norn's correlation interceptor. |
| `activityOverrides` | Replace registered activities by name (tests). Unknown names are rejected. |
| `extraActivities` | Activities that are not `@Activities` classes. |
| `workerOptions` | Passed to every `Worker.create()`: concurrency, sticky cache, pollers, interceptors. Norn sets the connection, namespace, task queue, activities, bundle, data converter, plugins, shutdown grace time and deployment options itself. |

### Lifecycle

`run()` starts polling every task queue (`RUNNING`) and resolves when the worker has stopped. On SIGTERM or SIGINT (with `handleSignals`), or when you call `shutdown()`:

1. The state becomes `STOPPING` and `/readyz` returns 503.
2. Every Temporal worker stops polling; in-flight activities get up to `shutdownGraceTime` before they are cancelled.
3. The container disposes singletons in reverse creation order, the health server closes and Norn closes the connection it opened.
4. `run()` resolves with the state `STOPPED`.

If one task queue's worker fails, the others are shut down and `run()` rejects (`FAILED`), so the process exits and your orchestrator restarts it. `shutdown()` before `run()` just releases resources. `await using worker = await createWorker(...)` shuts down at the end of the scope. Give your platform at least the grace time plus a margin to stop the process (`stopTimeout` on ECS, `terminationGracePeriodSeconds` on Kubernetes).

Signal caveats: `handleSignals: false` only removes Norn's own listener; the Temporal SDK runtime still stops running workers on SIGINT, SIGTERM, SIGQUIT and SIGUSR2. A second identical signal (two Ctrl-Cs, or a wrapper such as `pnpm run` forwarding one) gets Node's default action and exits at once, without draining. If you set `workerOptions.shutdownForceTime`, `run()` can end while activities that ignore cancellation are still running, and the container then disposes singletons underneath them.

## Health checks

With `NORN_HEALTH_PORT` or `health: { port }`:

| Endpoint | Response |
| --- | --- |
| `GET /healthz` | `200 {"status":"ok"}` while the process is alive. |
| `GET /readyz` | `200 {"status":"ready","details":{...}}` when every task queue's worker is running, otherwise `503 {"status":"not ready",...}`. `details` maps each queue to its SDK worker state. |

`HEAD` works too; other paths return 404 and other methods 405. `startHealthServer({ port, host?, ready })` is exported for processes that are not Norn workers; `ready` returns a boolean or `{ ready, details? }`.

## Metrics and logs: `installRuntime(options?, env?)`

```ts
function installRuntime(options?: { metricsAddress?: string; logLevel?: LogLevel }, env?: Record<string, string | undefined>): Runtime;
```

Installs the process-wide Temporal runtime with the SDK log level (`logLevel`, `NORN_LOG_LEVEL`, default `INFO`) and, with `metricsAddress` / `NORN_METRICS_ADDRESS` (`host:port`), a Prometheus endpoint for SDK and core metrics. Call it once at startup, before any connection or worker is created; it throws `NornConfigError` otherwise.

## Bundling workflows

In development `createWorker()` bundles the registry's workflows at startup. In production, build the bundle once and ship it, with `norn bundle` (from `@norn/cli`) or a script:

```ts
import { bundleWorkflows } from '@norn/worker';
import { resolvePayloadConverterPath } from '@norn/codec'; // only with @norn/codec's data converter
import { registry } from '../dist/.norn/registry.js';

await bundleWorkflows(registry, { outFile: 'dist/workflow-bundle.js', payloadConverterPath: resolvePayloadConverterPath() });
// then run workers with NORN_WORKFLOW_BUNDLE=dist/workflow-bundle.js
```

```ts
function bundleWorkflows(registry: Pick<NornRegistry, 'workflowsPath'>, options?: BundleWorkflowsOptions): Promise<{ code: string }>;
```

| `BundleWorkflowsOptions` | Description |
| --- | --- |
| `outFile` | Also write the bundle to this file. |
| `payloadConverterPath` | Required when workers use a custom payload converter. |
| `workflowInterceptorModules` | Extra workflow interceptor modules, after Norn's. |
| `plugins` | Temporal bundler plugins, such as the OpenTelemetry plugin (`createWorker()`'s own bundling does not pass `plugins`, so prebuild when you use them). |
| `webpackConfigHook` | Your hook, run after Norn's. |
| `ignoreModules` | Modules the bundler should ignore. |

For custom bundling setups:

- `nornWebpackConfigHook({ conditions? })`: the webpack config hook that switches Temporal's swc loader to standard decorators (`decoratorVersion: '2022-03'`, ES2022) and lets `.js` specifiers resolve to `.ts` sources. `conditions` defaults to `NORN_DEV_CONDITIONS`.
- `composeWebpackHooks(...hooks)`: runs several hooks in order.
- `workflowInterceptorModule`: the absolute path of Norn's workflow interceptor module, for `workflowInterceptorModules`. The same module is published as `@norn/worker/workflow-interceptors` (export `interceptors`); it forwards the correlation ID header to activities, local activities, child workflows, external signals and continue-as-new.

## The registry

`.norn/registry.ts` (generated) exports a `NornRegistry`:

```ts
interface NornRegistry {
  workflowsPath: string; // the generated workflows barrel (.ts in development, .js once compiled)
  taskQueues: readonly string[];
  workflows: readonly RegistryWorkflow[]; // { name, className, taskQueue }
  activities: readonly string[]; // registered names, including prefixes
  searchAttributes: Readonly<Record<string, SearchAttributeType>>;
  schedules: readonly ScheduleSpec[];
  createContainer(options?: RegistryContainerOptions): Container;
}
```

`defineRegistry(registry)` type-checks a hand-written one. `createTestEnv()` from `@norn/testing` and `norn schedules sync` read the same object.

## Other exports

- `resolveWorkerConfig(options, env?)`: resolves options, environment variables and defaults into a `ResolvedWorkerConfig` (task queues, address, namespace, TLS, deployment options, health port and host, grace time), throwing `NornConfigError` for invalid values. `createWorker()` calls it first; `worker.config` holds the result.
- `correlationActivityInterceptor`: the activity interceptor `createWorker()` installs; it runs each activity inside `runWithCorrelationId()` with the ID its workflow carried.
