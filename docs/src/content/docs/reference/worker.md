`@norn-ts/worker` turns the registry generated by `norn gen` into a production worker process. It runs one Temporal worker per task queue, builds activities with the dependency container, loads a prebuilt workflow bundle or bundles at startup, serves `/healthz` and `/readyz`, shuts down gracefully on SIGTERM, carries correlation IDs, and supports worker versioning and Prometheus metrics. Everything is configured from options or environment variables.

- **`createWorker({ registry })`**: everything above. Misconfiguration (unknown task queues, half-set versioning, bad ports or durations, a provider that cannot be built) fails at startup with a `NornConfigError`.
- **`bundleWorkflows()`**: bundles workflows with Norn's settings (TC39 standard decorators, `.js`→`.ts` resolution, the correlation interceptors), for shipping a prebuilt bundle.
- **`installRuntime()`**: the Temporal runtime with a log level and a Prometheus endpoint.

For the task-oriented walkthrough (Dockerfile, Kubernetes, choosing task queues), see [Worker & deployment](/norn/guides/worker/). Versioning is covered in [Versioning](/norn/guides/versioning/), metrics and correlation IDs in [Observability](/norn/guides/observability/).

## Install

```sh
pnpm add @norn-ts/worker @temporalio/worker @temporalio/workflow @temporalio/activity @temporalio/common @temporalio/client
```

Requires Node 22.18+ on a glibc-based system. The Temporal SDK's core is a native module, so use images such as `node:24-slim`, not Alpine. Add [`@norn-ts/cli`](/norn/reference/cli/) to generate the registry.

## Usage

```ts
// src/worker.ts
import { createWorker, installRuntime } from '@norn-ts/worker';
// optional: payload encryption
import { createDataConverter } from '@norn-ts/codec';
import { registry } from '../.norn/registry';

// NORN_LOG_LEVEL, NORN_METRICS_ADDRESS; before any connection or worker
installRuntime();

const worker = await createWorker({
  registry,
  // 4xx from providers are final, 5xx retried
  container: { errors: { http: true } },
  dataConverter: process.env.NORN_KEY ? createDataConverter({ keys: { k1: process.env.NORN_KEY }, currentKeyId: 'k1' }) : undefined,
});
// resolves after a graceful shutdown; rejects if a worker fails
await worker.run();
```

`createWorker()` resolves once everything is ready: every singleton dependency and activity is created (so a bad provider fails here), the connection is open, the workflow bundle is built or loaded, and the health server listens.

## Environment variables

| Variable | Option | Default | Description |
| --- | --- | --- | --- |
| `TEMPORAL_ADDRESS` | `address` | `localhost:7233` | Temporal frontend address. |
| `TEMPORAL_NAMESPACE` | `namespace` | `default` | Namespace to poll. |
| `TEMPORAL_API_KEY` | `apiKey` | none | API key; turns TLS on. |
| `TEMPORAL_TLS` | `tls` | `false` | `true` turns TLS on without an API key. For mTLS, pass your own `connection`. |
| `NORN_TASK_QUEUES` | `taskQueues` | every queue in the registry | Comma-separated subset to poll. |
| `NORN_HEALTH_PORT` | `health.port` | off | Health server port; `0` picks a free one. |
| `NORN_SHUTDOWN_GRACE` | `shutdownGraceTime` | `30s` | How long in-flight activities may run after shutdown starts. Any `Duration`. |
| `NORN_DEPLOYMENT_NAME` | `versioning.deploymentName` | none | Worker deployment name. Set together with `NORN_BUILD_ID`. |
| `NORN_BUILD_ID` | `versioning.buildId` | none | Build ID of this version, such as the git SHA. |
| `NORN_WORKFLOW_BUNDLE` | `workflowBundle` | bundle at startup | Path of a prebuilt bundle from `norn bundle` or `bundleWorkflows()`. |
| `NORN_DEV_CONDITIONS` | `nornWebpackConfigHook({ conditions })` | none | Comma-separated package export conditions for the bundler, such as a monorepo source condition. |
| `NORN_METRICS_ADDRESS` | `installRuntime({ metricsAddress })` | off | `host:port` (or `[ipv6]:port`) for Prometheus metrics. |
| `NORN_LOG_LEVEL` | `installRuntime({ logLevel })` | `INFO` | `TRACE`, `DEBUG`, `INFO`, `WARN` or `ERROR` (case-insensitive). |

Options win over environment variables. Empty variables count as unset, the same as in `createClient()` and the CLI. Setting only one of `NORN_DEPLOYMENT_NAME` and `NORN_BUILD_ID` is a startup error. `health: false` and `versioning: false` ignore the matching variables.

## `createWorker(options)`

```ts
function createWorker(options: CreateWorkerOptions): Promise<NornWorker>;

type NornWorkerState = 'INITIALIZED' | 'RUNNING' | 'STOPPING' | 'STOPPED' | 'FAILED';

interface NornWorker extends AsyncDisposable {
  readonly taskQueues: readonly string[];
  readonly state: NornWorkerState;
  // useful with health: { port: 0 }
  readonly healthPort: number | undefined;
  readonly config: ResolvedWorkerConfig;
  run(): Promise<void>;
  shutdown(): Promise<void>;
}
```

| Option | Default | Description |
| --- | --- | --- |
| `registry` | | **Required.** The `registry` from `.norn/registry.ts`. |
| `taskQueues` | `NORN_TASK_QUEUES`, then every queue in the registry | Subset of the registry's task queues to poll. An empty list is a startup error. |
| `allowUnknownTaskQueues` | `false` | Allow queues no workflow declares, for activity-only workers. Otherwise an unknown queue is a startup error. |
| `address` | `TEMPORAL_ADDRESS`, then `localhost:7233` | Temporal frontend address. |
| `namespace` | `TEMPORAL_NAMESPACE`, then `default` | Namespace to poll. |
| `apiKey` | `TEMPORAL_API_KEY` | API key; turns TLS on. |
| `tls` | `true` with an API key or `TEMPORAL_TLS=true` | `boolean`. For mTLS, pass your own `connection`. |
| `connection` | Norn connects | An existing `NativeConnection`. Norn closes only connections it opened. |
| `versioning` | from `NORN_DEPLOYMENT_NAME` + `NORN_BUILD_ID` | `{ deploymentName, buildId, defaultBehavior? }`, or `false` to ignore the environment. `defaultBehavior` is `'auto-upgrade'` (default) or `'pinned'`, for workflows that don't set `versioning` in `@Workflow`. |
| `health` | `NORN_HEALTH_PORT`, else off | `{ port, host? }` (`host` defaults to `0.0.0.0`), or `false`. |
| `shutdownGraceTime` | `NORN_SHUTDOWN_GRACE`, then `30s` | A `Duration`. |
| `handleSignals` | `true` | Shut down gracefully on SIGTERM and SIGINT. |
| `container` | | `{ overrides?, errors? }` for the dependency container: replace dependencies, and map activity errors (`errors: { http, map }`, see [error mapping](/norn/reference/activity/#error-mapping)). |
| `workflowBundle` | `NORN_WORKFLOW_BUNDLE`, else bundle at startup | `{ code }` or `{ codePath }` of a prebuilt bundle. |
| `dataConverter` | | Such as `createDataConverter()` from [`@norn-ts/codec`](/norn/reference/codec/). Its `payloadConverterPath` is used when bundling at startup. |
| `plugins` | | Temporal worker plugins. Also applied when bundling at startup. |
| `activityOverrides` | | Replace registered activities by name (tests). Unknown names are rejected. |
| `workerOptions` | | Passed to every `Worker.create()`: concurrency, sticky cache, pollers, interceptors. |

Norn sets the connection, namespace, task queue, activities, bundle, data converter, plugins, bundler options, shutdown grace time and deployment options itself; `workerOptions` can't override them. Activity interceptors in `workerOptions.interceptors.activity` run after Norn's correlation interceptor.

Startup errors: invalid options throw `NornConfigError`. A connection that can't be opened (or a worker that can't reach the server) throws `TemporalUnavailableError`. A health port that can't be bound throws `NornConfigError`. Whatever was already created is released before the error is thrown.

### Lifecycle

`run()` starts polling every task queue (`RUNNING`) and resolves when the worker has stopped. Calling it again returns the same promise; calling it after a shutdown rejects with `NornConfigError`. On SIGTERM or SIGINT (with `handleSignals`), or when you call `shutdown()`:

1. The state becomes `STOPPING` and `/readyz` returns 503.
2. Every Temporal worker stops polling; in-flight activities get up to `shutdownGraceTime` before they are canceled.
3. The container disposes singletons in reverse creation order, the health server closes and Norn closes the connection it opened.
4. `run()` resolves with the state `STOPPED`.

If one task queue's worker fails, the others are shut down and `run()` rejects (`FAILED`), so the process exits and your orchestrator restarts it. `shutdown()` before `run()` just releases resources. `await using worker = await createWorker(...)` shuts down at the end of the scope. Give your platform at least the grace time plus a margin to stop the process (`stopTimeout` on ECS, `terminationGracePeriodSeconds` on Kubernetes).

:::caution[Signal caveats]
`handleSignals: false` only removes Norn's own listener; the Temporal SDK runtime still stops running workers on SIGINT, SIGTERM, SIGQUIT and SIGUSR2. A second identical signal (two Ctrl-Cs, or a wrapper such as `pnpm run` forwarding one) gets Node's default action and exits at once, without draining. If you set `workerOptions.shutdownForceTime`, `run()` can end while activities that ignore cancellation are still running, and the container then disposes singletons underneath them.
:::

### `resolveWorkerConfig(options, env?)`

```ts
function resolveWorkerConfig(options: WorkerConfigOptions, env?: Record<string, string | undefined>): ResolvedWorkerConfig;
```

Resolves options, environment variables (`env` defaults to `process.env`) and defaults into a `ResolvedWorkerConfig`: `taskQueues`, `address`, `namespace`, `apiKey`, `tls`, `deployment` (Temporal's `WorkerDeploymentOptions`), `healthPort`, `healthHost`, `shutdownGraceTime` (as `'<n>ms'`) and `handleSignals`. It throws `NornConfigError` for invalid values. `createWorker()` calls it first; `worker.config` holds the result. `WorkerConfigOptions` is the subset of `CreateWorkerOptions` it reads: `registry`, `taskQueues`, `allowUnknownTaskQueues`, `address`, `namespace`, `apiKey`, `tls`, `versioning`, `health`, `shutdownGraceTime` and `handleSignals`. `NORN_WORKFLOW_BUNDLE` and `NORN_DEV_CONDITIONS` are read from `process.env` elsewhere, not from `env`.

## Health checks

With `NORN_HEALTH_PORT` or `health: { port }`:

| Endpoint | Response |
| --- | --- |
| `GET /healthz` | `200 {"status":"ok"}` while the process is alive. |
| `GET /readyz` | `200 {"status":"ready","details":{...}}` when every task queue's worker is running, otherwise `503 {"status":"not ready",...}`. `details` maps each queue to its SDK worker state. |

`HEAD` works too; other paths return 404 and other methods 405. Responses are JSON with `cache-control: no-store`.

### `startHealthServer(options)`

```ts
function startHealthServer(options: HealthServerOptions): Promise<HealthServer>;

interface HealthServerOptions {
  port: number;
  // default '0.0.0.0'
  host?: string;
  ready: () => Readiness;
}
type Readiness = boolean | { ready: boolean; details?: Record<string, unknown> };
interface HealthServer {
  readonly port: number;
  close(): Promise<void>;
}
```

The same server, for processes that are not Norn workers. A `ready()` that throws counts as not ready. The promise rejects if the port can't be bound.

## Metrics and logs: `installRuntime(options?, env?)`

```ts
function installRuntime(options?: InstallRuntimeOptions, env?: Record<string, string | undefined>): Runtime;

interface InstallRuntimeOptions {
  // default NORN_METRICS_ADDRESS
  metricsAddress?: string;
  // default NORN_LOG_LEVEL, then 'INFO'
  logLevel?: LogLevel;
}
```

Installs the process-wide Temporal runtime with the SDK log level and, with `metricsAddress` (`host:port`, such as `'0.0.0.0:9464'` or `'[::]:9464'`), a Prometheus endpoint for SDK and core metrics. Call it once at startup, before any connection or worker is created; it throws `NornConfigError` otherwise, and for an unknown log level or a malformed address. See [Observability](/norn/guides/observability/#metrics).

## Bundling workflows

In development `createWorker()` bundles the registry's workflows at startup. In production, build the bundle once and ship it, with [`norn bundle`](/norn/reference/cli/) or a script:

```ts
import { bundleWorkflows } from '@norn-ts/worker';
// only with @norn-ts/codec's data converter
import { resolvePayloadConverterPath } from '@norn-ts/codec';
import { registry } from '../dist/.norn/registry';

await bundleWorkflows(registry, { outFile: 'dist/workflow-bundle.js', payloadConverterPath: resolvePayloadConverterPath() });
// then run workers with NORN_WORKFLOW_BUNDLE=dist/workflow-bundle.js
```

```ts
function bundleWorkflows(registry: Pick<NornRegistry, 'workflowsPath'>, options?: BundleWorkflowsOptions): Promise<{ code: string }>;
```

| `BundleWorkflowsOptions` | Description |
| --- | --- |
| `outFile` | Also write the bundle to this file (parent directories are created). |
| `payloadConverterPath` | Required when workers use a custom payload converter. |
| `workflowInterceptorModules` | Extra workflow interceptor modules, after Norn's. |
| `plugins` | Temporal bundler plugins, such as the OpenTelemetry plugin. |
| `webpackConfigHook` | Your hook, run after Norn's. |
| `ignoreModules` | Modules the bundler should ignore. |

See [Production builds](/norn/guides/worker/#production-builds-compile-then-bundle) for the full build pipeline.

### Custom bundling setups

- `nornWebpackConfigHook({ conditions? })`: the webpack config hook that switches Temporal's swc loader to standard decorators (`decoratorVersion: '2022-03'`, ES2022) and lets `.js` specifiers resolve to `.ts` sources. `conditions` defaults to `NORN_DEV_CONDITIONS`. Compiled JavaScript passes through untouched. `NornBundlerOptions` is its options type and `WebpackLikeConfig` the minimal config shape it accepts.
- `composeWebpackHooks(...hooks)`: runs several hooks in order, skipping `undefined` ones.
- `workflowInterceptorModule`: the absolute path of Norn's workflow interceptor module, for `workflowInterceptorModules`. The same module is published as `@norn-ts/worker/workflow-interceptors` (export `interceptors`). It forwards the correlation ID header to activities, local activities, child workflows, external signals and continue-as-new.

## The registry

`.norn/registry.ts` (generated) exports a `NornRegistry`:

```ts
interface NornRegistry {
  // the generated workflows barrel (.ts in development, .js once compiled)
  workflowsPath: string;
  taskQueues: readonly string[];
  // registered names, including prefixes
  activities: readonly string[];
  searchAttributes: Readonly<Record<string, SearchAttributeType>>;
  createContainer(options?: RegistryContainerOptions): Container;
}

interface RegistryContainerOptions {
  overrides?: ReadonlyArray<readonly [InjectionKey, unknown]>;
  errors?: ErrorMappingOptions;
}
```

`defineRegistry(registry)` type-checks a hand-written one. `createTestEnv()` from [`@norn-ts/testing`](/norn/reference/testing/) reads the same object.

`ScheduleSpec` is the shape of each entry in `.norn/schedules.json`, which `norn schedules sync` reads: `id`, `workflowType`, `taskQueue`, `cron` (a list), and optionally `input`, `overlap` (`ScheduleOverlap`), `timeZone`, `pauseOnFailure`, `paused` and `note`.

## Correlation interceptor

`correlationActivityInterceptor` is the activity interceptor factory `createWorker()` installs. It runs each activity inside `runWithCorrelationId()` with the ID its workflow carried. See [Correlation IDs](/norn/guides/observability/#correlation-ids).
